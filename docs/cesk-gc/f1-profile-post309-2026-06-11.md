## Findings

1. **`inner_ref_index` GREW: 16.6% (467d8afe profile) → 22.4–24.2%.** Each landed
   lever shrank everything around it; the materialize-per-access core concentrated.
   Experiment #15 (REJECT, `ea430f9c`) refuted the RefCell borrow-RMW theory for this
   symbol — the cost is the dependent page-chase loads + per-access epoch check
   themselves, not the borrow bookkeeping (MLP hides the RMW under the loads).
2. **#2 is bulk copying: ~18.6% of Robot inside libc memmove** (the anonymous
   `0x172164–0x1721a2` cluster = `__memmove_avx_unaligned_erms`). Direct stack
   evidence ties part of it to `SlabAllocator::alloc_data` (the materialization
   path's payload copies — index-mode `materialize_inner` Box-allocates and copies
   node payloads out of the index heap). Caller attribution is INCOMPLETE: the
   dwarf unwind failed on most leaf samples (no frame pointers in the build).
3. `as_atom` (~8%) sits directly on top of `inner_ref_index` — same path.
4. Sum: **~49% of Robot wall is materialize-per-access machinery** (chase + copy +
   accessor), matching the standing architectural diagnosis. No GC-phase symbol
   (mark/sweep/rendezvous) appears above 2% — the collector itself is not the gap.

## Next-lever candidates (for the NEXT pre-registered experiment — pgmcp pool was
down at profile time; register before implementing, per the mandate)

- **(a) Attack the copy, not the bookkeeping**: serve stable interned references
  for node payloads (in-place reads like slab) instead of materialize-by-copy —
  targets #1+#2 jointly (~40%+ of wall). Requires an epoch/ABA-safe reference
  contract (the laundered-&'static audit + per-cell generations are prior art).
- **(b) Precise memmove attribution first** (cheap, 10 min): rebuild with
  `-Cforce-frame-pointers=yes`, re-profile `--call-graph fp`, split memmove time
  between `alloc_data` / `materialize_inner` / `Vec` growth before locking (a)'s
  design scope.
- (c) `as_atom`/`as_sexpr` fast paths only AFTER (a) — they amortize into it.
