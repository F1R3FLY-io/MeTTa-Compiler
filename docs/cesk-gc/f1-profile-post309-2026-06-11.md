## Findings

1. **`inner_ref_index` GREW: 16.6% (467d8afe profile) → 22.4–24.2%.** Each landed
   lever shrank everything around it; the materialize-per-access core concentrated.
   Experiment #15 (REJECT, `ea430f9c`) refuted the RefCell borrow-RMW theory for this
   symbol — the cost is the dependent page-chase loads + per-access epoch check
   themselves, not the borrow bookkeeping (MLP hides the RMW under the loads).
2. **#2 is bulk copying: ~18.6% of Robot inside libc memmove** (the anonymous
   `0x172164–0x1721a2` cluster = `__memmove_avx_unaligned_erms`). **ATTRIBUTED**
   via a frame-pointer rebuild + `--call-graph fp` re-profile
   (`robot_f0_fp.perf.data`, 13,774 samples, full unwind): **2,459/13,774
   samples (~17.9%) are libc frames called directly from
   `eval::expression_involves_rule_rhs_atom`** (`src/backend/eval/mod.rs:1131`)
   — the recursive bytecode-path gate behind `expression_involves_cut_rules` /
   `expression_involves_impure_rules`. The walk is structurally copy-free, but
   in index mode its inlined accessors (`as_sexpr`/`inner_ref_index`
   materialization) COPY the children vector at every recursion level, and the
   gate re-walks the WHOLE expression per eval dispatch. Long tail: trampoline
   work-item clones (~3%), `compose_outer_inner_generic` (~0.7%).
3. `as_atom` (~8%) sits directly on top of `inner_ref_index` — same path.
4. Sum: **~49% of Robot wall is materialize-per-access machinery** (chase + copy +
   accessor), matching the standing architectural diagnosis. No GC-phase symbol
   (mark/sweep/rendezvous) appears above 2% — the collector itself is not the gap.

## Next-lever candidates (for the NEXT pre-registered experiment — pgmcp pool was
down at profile time; register before implementing, per the mandate)

- **(a) TOP LEVER — kill the per-dispatch impure/cut gate walk's copies** (the
  sharpest target, from the FP attribution): the gate re-walks + re-materializes
  the whole expression tree per eval dispatch. Gap arithmetic at this profile:
  memmove 18.6%×13.99s ≈ 2.60s + 3.34% self ≈ 0.47s ⇒ **~3.1s of Robot's 3.72s
  index-vs-slab gap is this single site** (slab pays only the walk — in-place
  reads; index pays per-level copies).

  **Design scoping (source-verified 2026-06-11):** `rule_rhs_contains_atom`
  is already a cheap per-head set lookup (`PerHeadAtomIndex` refcounted at
  rule add/remove, `rule_management.rs:784`) and is **NON-transitive over the
  rule graph** — the expression walk supplies the coverage. Therefore:
  1. ~~Per-head transitive closure~~ — REJECTED at design time: it would
     CHANGE gate verdicts (route more expressions off the bytecode path), a
     behavior change the exp14 veto class warns about. Do not pursue first.
  2. **RECOMMENDED NEXT EXPERIMENT — index-native copy-free walk**: walk the
     expression's child `Addr`s in place (head symbol + children straight from
     heap nodes, no `as_sexpr`/shadow materialization). Byte-identical gate
     verdicts by construction ⇒ conformance/determinism-safe; targets the
     full ~18% memmove. Projected Robot ≈ 1.08–1.1× if the memmove dies.
  3. Memoize the verdict per (expression identity, rule-generation) — exact
     invalidation on rule add/remove; helps BOTH backends; follow-up if (2)
     leaves residual walk cost (3.3% self).
- (b) Materialize-per-access architecture (`inner_ref_index` 22%, `as_atom` 8%)
  — the bigger, riskier rework; only if (a) leaves F1 above the bar.
- (c) `as_atom`/`as_sexpr` micro fast paths only after (a)/(b).

## ⚠️ ADDENDUM (2026-06-12, experiment #16): the FP memmove attribution above is REFUTED BY INTERVENTION

The recommended lever (index-native copy-free gate walk) was implemented
verdict-identically (conformance 483/0 + an 11-case differential oracle) and
measured at **p=0.416, Cohen's d=−0.04** (Robot FANOUT=0, n=51/arm,
interleaved rounds) — a pure null. Removing ALL of the gate's materialization
moved nothing, so the "2,459/13,774 samples of memmove called from
`expression_involves_rule_rhs_atom`" finding was an unwind artifact: the
frame-pointer unwinder walks a STALE rbp chain through the frameless AVX
memmove leaf and mis-attributes its caller (the dwarf profile had already
failed to unwind those same leaves — finding #2's caller claim should not
have been accepted from FP data alone). The gate's shadow accesses are
evidently warm cache hits (consistent with exp14: the per-access epoch CHECK,
not materialization, was that path's measured cost).

**Standing method rule for this campaign:** on Zen 3, sampled caller
attribution of frameless libc leaves is unreliable under BOTH `--call-graph
dwarf` (unwind failures) and `--call-graph fp` (stale rbp). Attribute hot
libc leaves only via exact call graphs (`valgrind --tool=callgrind`, no
sampling) or via intervention experiments (the exp16 pattern). The ~18.6%
memmove total (leaf SELF time — trustworthy) remains REAL but UNATTRIBUTED;
finding its caller via callgrind is the campaign's next step. The
self-time table (finding #1, #3, #4) is unaffected: leaf self needs no unwind.

Patch archived: `docs/cesk-gc/rejected-patches/exp16-copy-free-gate-walk.patch`
(collector + dispatch + differential test, recoverable). pgmcp experiment #16,
observation 212.

## ✅ EXACT ATTRIBUTION (2026-06-12): callgrind settles it — the memcpy is the needle-check's double-intern

`valgrind --tool=callgrind` on Robot FANOUT=0 (`robot_f0.callgrind`, 170.6B Ir,
exact call graph, no sampling):

| function | exact Ir share |
|---|---|
| `inner_ref_index` | **32.94%** — callers: `as_atom` 297.9M calls (9.48%), `as_sexpr` 243.8M (7.81%), `collect_variables_generic` 195.4M (6.18%), `as_atom'2` 115.1M (3.64%), `as_error` 64.3M (2.04%) |
| `__memcpy_avx_unaligned_erms` | **21.17%** — callers: `SlabAllocator::alloc_data` **16.87%** (60.1M calls), `eval_trampoline_inner'2` 1.96%, the gate **0.25%** (independently confirming exp16's null) |
| `collect_variables_generic` | 5.21% |
| sip `Hasher::write` | 2.79% (intern-table hashing) |
| `as_atom` | 2.70% self |

And `alloc_data`'s dominant caller is the **impure/cut gate's needle check**:
`expression_involves_rule_rhs_atom'2 → alloc_data`, 29.76M calls, **31.5B Ir
= 18.46% of the program inclusive** — i.e. `PerHeadAtomIndex::contains`
(`rule_management.rs:775`) **interns BOTH query strings via
`global_allocator().alloc_str` on every membership check**, purely to build a
`(&'static str, &'static str)` tuple key. The index-vs-slab asymmetry: index
atoms live in the index interner, so the slab `alloc_str` MISSES and byte-
copies every time; slab-mode heads are already slab-interned and mostly hit —
this asymmetry is a direct, quantified contributor to the F1 gap.

**→ Experiment #17 (pre-registered, criterion frozen): intern-free nested
`HashMap<&'static str, HashMap<&'static str, u32>>` with `Borrow<str>`
lookups at both levels — zero interning/allocation per check, byte-identical
membership semantics. Projected from the exact Ir share: Robot ~14.45s →
~11.5–12.5s (1.36× → ~1.12–1.21×).**

shared-code lever shifts BOTH stores — ratio projections must model the
