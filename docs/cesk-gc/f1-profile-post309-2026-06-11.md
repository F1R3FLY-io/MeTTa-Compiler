## Findings

1. **`inner_ref_index` GREW: 16.6% (467d8afe profile) → 22.4–24.2%.** Each landed
   lever shrank everything around it; the materialize-per-access core concentrated.
   Experiment #15 (REJECT, `ea430f9c`) refuted the RefCell borrow-RMW theory for this
   symbol — the cost is the dependent page-chase loads + per-access epoch check
   themselves, not the borrow bookkeeping (MLP hides the RMW under the loads).
2. **#2 is bulk copying: ~18.6% of Robot inside libc memmove** (the anonymous
   `0x172164–0x1721a2` cluster = `__memmove_avx_unaligned_erms`). **ATTRIBUTED**
   via a frame-pointer rebuild + `--call-graph fp` re-profile
   (`robot_f0_fp.perf.data`, 13,774 samples, full unwind): **2,459/13,774
   samples (~17.9%) are libc frames called directly from
   `eval::expression_involves_rule_rhs_atom`** (`src/backend/eval/mod.rs:1131`)
   — the recursive bytecode-path gate behind `expression_involves_cut_rules` /
   `expression_involves_impure_rules`. The walk is structurally copy-free, but
   in index mode its inlined accessors (`as_sexpr`/`inner_ref_index`
   materialization) COPY the children vector at every recursion level, and the
   gate re-walks the WHOLE expression per eval dispatch. Long tail: trampoline
   work-item clones (~3%), `compose_outer_inner_generic` (~0.7%).
3. `as_atom` (~8%) sits directly on top of `inner_ref_index` — same path.
4. Sum: **~49% of Robot wall is materialize-per-access machinery** (chase + copy +
   accessor), matching the standing architectural diagnosis. No GC-phase symbol
   (mark/sweep/rendezvous) appears above 2% — the collector itself is not the gap.

## ⚠️ ADDENDUM (2026-06-12, experiment #16): the FP memmove attribution above is REFUTED BY INTERVENTION

The recommended lever (index-native copy-free gate walk) was implemented
verdict-identically (conformance 483/0 + an 11-case differential oracle) and
measured at **p=0.416, Cohen's d=−0.04** (Robot FANOUT=0, n=51/arm,
interleaved rounds) — a pure null. Removing ALL of the gate's materialization
moved nothing, so the "2,459/13,774 samples of memmove called from
`expression_involves_rule_rhs_atom`" finding was an unwind artifact: the
frame-pointer unwinder walks a STALE rbp chain through the frameless AVX
memmove leaf and mis-attributes its caller (the dwarf profile had already
failed to unwind those same leaves — finding #2's caller claim should not
have been accepted from FP data alone). The gate's shadow accesses are
evidently warm cache hits (consistent with exp14: the per-access epoch CHECK,
not materialization, was that path's measured cost).

**Standing method rule for this campaign:** on Zen 3, sampled caller
attribution of frameless libc leaves is unreliable under BOTH `--call-graph
dwarf` (unwind failures) and `--call-graph fp` (stale rbp). Attribute hot
libc leaves only via exact call graphs (`valgrind --tool=callgrind`, no
sampling) or via intervention experiments (the exp16 pattern). The ~18.6%
memmove total (leaf SELF time — trustworthy) remains REAL but UNATTRIBUTED;
finding its caller via callgrind is the campaign's next step. The
self-time table (finding #1, #3, #4) is unaffected: leaf self needs no unwind.

Patch archived: `docs/cesk-gc/rejected-patches/exp16-copy-free-gate-walk.patch`
(collector + dispatch + differential test, recoverable). pgmcp experiment #16,
observation 212.

### Next-lever design seed (needs red-team convergence BEFORE registration —
it changes the core handle representation)

**Handle-borne type tags**: the `MettaValue` tagged word has free bits
[47:36] (Addr occupies [35:4], flags [3:0], NaN-box [63:48]). Stash the
node's variant tag (5 bits covers the 18 `Node` variants) at handle-creation
time (factory intern sites + `from_addr` reconstruction). Every `as_*`/`is_*`
variant check then answers from the HANDLE REGISTER — no TLS, no page chase,
no lock; only true hits (and `Spanned`, which is accessor-transparent and
must fall through) proceed to materialize. Index variant checks would become
CHEAPER than slab's (zero derefs vs one).
Design hazards to red-team: every handle-construction site must set the tag
consistently (hash-cons/equality on the tagged word are unaffected ONLY if
same-node ⇒ same-tag, as flags already guarantee); E4 continuation slices
persist `(raw, flags)` and must persist/reconstruct the tag bits; the DEBUG
machine-equivalence oracle must verify tag-vs-node agreement (a permanent
tripwire, the exp15 pattern); `Spanned` wrapping at compile time could
shrink the fast-path coverage on span-heavy values — measure the
tag-distribution first (cheap instrumentation pass).

### Lever (b) design seed — ARENA-CORESIDENT INNER COLUMN (red-team before
registering; this is the architectural endgame for read parity)

Today a positive accessor call pays the per-(thread, Addr) shadow: TLS +
page chase + epoch check on hits; lock + Box::new(materialize) on misses —
because the shadow CACHE outlives nodes (hence the epoch/ABA machinery).
Instead: build the `MettaValueInner` ONCE at intern time into a parallel
arena column co-resident with the node (the children slice address is
already stable at intern — B2's never-realloc segments — so
`Inner::SExpr(laundered slice)` is computable there); `inner_ref_index`
becomes TWO LOADS (column base + offset) returning `&'static Inner` INTO
THE ARENA — exactly slab's one-indirection read discipline.
- **No epoch needed**: the column entry shares the NODE's lifetime (swept
  together; Addr reuse REWRITES the entry at re-intern; handles to swept
  nodes cannot exist by collector soundness — the same argument as I2).
- **Deletes the whole INNER_SHADOW subsystem** (TLS pages, epoch
  handshake, clear_inner_shadow, the mmverify fresh-thread cost class).
- Costs to red-team: +~40-48B/node column RSS (vs the 0.43-0.62× memory
  advantage — and minus the per-thread shadow RSS it deletes); intern-time
  Inner construction (once per node, amortized vs per-thread-per-access);
  sweep/segment-release must drop column entries (side-column precedent
  exists); Spanned launder lifetimes; concurrent intern publication order
  (Release on the column before the Addr escapes); Space/Memo handle
  clones in the column (Arc lifecycle vs the side-table id indirection —
  maybe keep ids and materialize ONLY those two variants lazily).
- ~~Projected: positive-call cost → slab-equal ⇒ Robot ratio ≈ 1.05-1.15×~~

### R1 (2026-06-12, source-verified) — one FALSIFICATION + the projection collapsed

- **F2 FALSIFIED (CRITICAL)**: "the column entry is rewritten exactly at
  re-intern before the new Addr escapes" describes a mechanism that DOES
  NOT EXIST — `write_reused` (index_arena.rs:710-722) overwrites the Node
  with no column counterpart. The design must BUILD the reuse-rewrite
  protocol: (A) per-entry generation guard (the SideColumn precedent) so
  deferred side-reclaim snapshots referencing stale column entries are
  gen-rejected, or (B) segment-release-only reclamation for column

  HANDLE-side argument (stale handles to swept nodes cannot exist) stands;
  the hazard is the column's own write-at-reuse ordering + stale
