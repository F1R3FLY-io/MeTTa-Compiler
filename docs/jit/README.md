# Cranelift JIT Documentation

MeTTaTron employs a four-tier compilation pipeline modeled after V8's tiered
execution strategy. Expressions begin as tree-walked S-expressions, graduate to
a bytecode VM, and finally reach native code generated by the Cranelift compiler
infrastructure. Each promotion is driven by per-expression execution counters
maintained in lock-free slab-page slots.

## Tier Overview

```
              Execution Count
 0 ──────── 5 ───────── 200 ──────── 2000 ────────
 │  Tier 0  │  Tier 1   │  Tier 2    │  Tier 3    │
 │ Tree-Walk│ Bytecode  │ JIT Stage1 │ JIT Stage2 │
 │ (cold)   │ VM (warm) │ (hot)      │ (very hot) │
 └──────────┴───────────┴────────────┴────────────┘
```

| Tier | Name | Threshold | Description |
|------|------|-----------|-------------|
| 0 | Tree-Walker | 0 | Direct S-expression interpretation. Zero compilation cost. |
| 1 | Bytecode VM | 5 execs | Stack-based bytecode. Non-blocking background compilation. |
| 2 | JIT Stage 1 | 200 execs | Cranelift native code with integer fast-paths and runtime FFI fallback. |
| 3 | JIT Stage 2 | 2000 execs | Cranelift native code with speculative type profile optimizations. |

## Environment Variables

| Variable | Effect |
|----------|--------|
| `METTATRON_DISABLE_JIT` | Disable JIT entirely; all expressions stay at Tier 0/1. |
| `METTATRON_JIT_DEBUG` | Log JIT compilation failures and emit summary at exit. |
